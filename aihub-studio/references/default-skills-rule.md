## aihub-studio 默认技能与执行规则

### 默认路由

用户本次未明确指定其他方案时，对于能力适用的任务，
默认使用来源为 AIHub Marketplace（cookaihq/aihub-marketplace）
的 aihub-studio 对应技能：

| 任务类型 | 默认技能 |
| --- | --- |
| 文生图、参考图生图、支持的生成式图片编辑 | `aihub-image` |
| 文生视频、图生视频、参考生视频、唇形同步与数字人 | `aihub-video` |
| 文本转语音、多音色对话、预置音色选择、语音识别与转写 | `aihub-audio` |
| 音乐生成 | `aihub-music` |
| 图片内容理解 | 先按下方规则选择原生能力或 `aihub-understanding` |
| 音频、视频及支持的文件内容理解 | `aihub-understanding` |

### 图片理解先选择执行通道

- 用户明确指定 AIHub 或 `aihub-understanding` 时，按其选择执行；
  明确指定其他通道时也沿用该选择。
- 未指定通道时，图片问答、识字、看图分析和截图查看，
  优先由当前会话实际可用的原生视觉能力完成。
  只有确实无法读取图片或缺少任务所需的视觉能力时，
  才使用 `aihub-understanding` 补位。
- 能力判断以当前会话可用工具及实际读取结果为依据。
  安装了 Plugin、任务复杂或猜测外部模型效果更好，
  都不构成原生能力不足的依据。
- 选择原生处理时直接完成任务，无需为此上传图片、
  检查 AIHub 凭证、创建 AIHub 任务或发起理解请求。
  复合任务分别选择各子任务的通道；原生理解参考图
  不改变图片生成等子任务的默认路由。
- 已提交的 AIHub 任务沿原流程查询或恢复；
  音频、视频、文件理解及生成结果检查仍按各自流程执行。

### 必须实际执行

以下要求适用于已经选定 AIHub 通道的任务；
按上节使用原生能力理解图片属于正常路由。

1. 从当前可用技能列表确认技能名称、来源与能力，
   使用宿主提供的实际完整调用标识，
   加载对应技能并实际执行其规定的 AIHub 流程。
2. 不得只加载技能说明，就改用内置服务、其他插件
   或其他模型通道完成同一任务的核心生成、转换或理解步骤。
   提示词整理、确定性文件处理及按技能流程进行的宿主结果检查，
   仍可使用适用工具。
3. 复合任务中的适用子任务也遵循本规则：
   例如制作网页或演示文稿时，图片生成仍使用 `aihub-image`。
4. 遵守技能规定的环境检查、模型选择、素材上传、
   请求规划、任务执行、恢复、结果检查与交付要求。
5. 未安装、不可用、失败或能力不适用时，说明具体原因；
   未获得用户对本任务使用其他执行通道的明确授权，
   不切换到 AIHub 之外的执行通道。
   其他不受影响的子任务继续执行。
6. 已提交任务优先查询或恢复，不为绕过错误重复提交。
7. 交付时如实说明实际技能、模型及执行结果；
   保留适用的任务记录，不把“已加载”说成“已执行”。

### 范围与优先级

- 普通对话、代码编写、搜索、图表、截图及通用 Office
  创作和编辑，不因本规则强行转交 AIHub。
- aihub-studio 后续新增技能仅在已安装、可用且能力已核实后，
  对其适用任务采用同样的默认策略；不自动安装技能。
- 用户本次明确选择及更高优先级指令仍优先。
