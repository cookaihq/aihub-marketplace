# 调用异常反馈与本地报告

五个 Skill 共用请求捕获和反馈摘要。`feedback.user_notice` / `advice` 供 Agent 判断当前结果与下一步；完整排障证据保存在本机。摘要只描述状态，不执行恢复，也不替代 Agent 的实际处理。

## 向用户说明当前结果

发生失败、结果待确认、部分完成或恢复时，先用普通语言说明：哪项操作未完成、停在哪一步、对可用结果的影响、证据支持的原因，以及下一步由谁做什么。结合原始需求和实际操作改写程序摘要；已经执行的动作和准备执行的动作分别说明。

- 有原任务可查询、文件可继续取得或其他已授权排查可做时，继续处理原任务，再反馈进展。确实需要用户提供信息、修复账号或作出选择时，说明具体操作及原因。
- 原因未查明就说尚未确认，并说明下一项可核对的证据。`service_unavailable` 不能证明供应商宕机；超时或提交结果不明不能说成确定失败，也不能保证未计费。
- 区分提交、查询、远端执行、下载、本地保存和结果检查。查询失败不能证明任务执行失败；下载失败先恢复已有结果；检查失败或不符合要求时仍交付已取得的结果，并说明缺少的检查或具体差异。
- 部分完成时说明哪些已可用、哪些缺失，以及会限制哪些结论。例如只读到字幕和关键帧时，明确尚未完成音轨或完整视频分析，不能冒充完整音画分析。
- 恢复成功后以当前成果和检查结论为主。历史错误继续留档，不能把历史鉴权、模型或选项错误作为当前阻塞；反复查询没有新进展时简短说明即可，无需重复错误次数和相同附件。
- 服务明确不支持选项时，读取完整 `message`、`unsupported_parameters` 和 `suggested_remove_parameters`，逐项解释影响用户的要求。让用户选择保留要求稍后处理，或明确修改后新建请求；不自动删参、换音色或改变要求。退款仅按实际证据说明。

模型切换、付费与确认门继续按原流程执行。`next_action` 是恢复线索，含确认 token 也不代表用户已同意。生成、上传或检查提交不明时先核对原请求，不为改善提示、补日志或报告写入失败创建替代请求。

## 按需提供排障材料

默认回复聚焦业务结果和下一步。内部状态名、错误计数、Skill 条文、原始 JSON、完整日志路径和 HTML 折叠标签留在排障过程，不作为默认回复正文。

`artifact_links` 是已存在证据文件的清单，供 Agent 定位；`show_notice=true` 表示有可用反馈，不要求逐条展示文件。用户需要查看报告、当前排查确实需要其检查，或准备反馈问题时，可提供一条 `[排障报告](实际的 error_report 绝对路径)`；使用简短、有意义的文字和真实文件目标。只有需要具体证据时再补充诊断、请求上下文或公开草稿，不因每次查询、恢复或最终答复而重复列出所有链接。业务成果文件仍按原交付流程提供。

`feedback_warning` 或 `feedback.warning` 表示报告或请求上下文可能未完整保存。说明这个限制，保留原任务状态、任务编号与已完成文件；已有报告可能过期，只链接实际存在的文件。没有报告文件时仍解释当前业务结果及下一步，不因记录失败重发请求。

## 证据含义

第一次 HTTP 请求失败、成功 HTTP 中的无效协议响应或远端任务执行失败时，保存 `error-report.md`、`diagnostic.json` 和 `issue-draft.md`。请求上下文另存 `request-context.json`，正常请求也保留脱敏提交证据。生成任务及其模型切换、结果检查共用同一目录。后续更新同一份记录；同一终止任务反复查询不增加错误数，每次实际失败的 HTTP 尝试分别计数。仅有本地下载等问题、没有接口错误时，`feedback` 可以只有当前摘要，不虚构接口错误或报告链接。

- `http_status` 只代表**客户端实际收到的 AIHub HTTP 响应**，来源为 `client_response`；没收到或没采集时为 null。异步 `task_status=failed` 可以出现在 HTTP 200/201 等响应里。
- `upstream` 保存 API 实际返回的供应商状态、错误详情、request ID、trace ID、路由、内部重试等字段，并标出 `source`。未暴露的信息一律未知，不能用模型名称猜供应商，也不能把 `service_unavailable` 解释为已证实上游宕机。需进一步定位时，建议管理员按本地报告中的任务/请求 ID 查后台日志。
- 每次 exchange 保存时间、地址、方法、实际请求/响应 JSON、响应头、客户端耗时、超时预算与可观察阶段、尝试序号及既有重试决定。客户端耗时不是供应商内部耗时；没有真实证据的阶段和字段保持 null。
- `original_request` 来自新任务 JSON 的用户原话，与实际提交 prompt/参数分开。旧命令或仅凭 task ID 恢复时缺少原文就显示未知，不能用 Agent 改写的 prompt 回填。
- API Key、Authorization、Cookie、凭证字段与 URL 查询签名脱敏。素材保留资源路径和必要参数信息；二进制、大型 Base64、过长内容明确标注省略。未知业务字段和错误码仍在本地报告中保留。

旧 schema 1 的 `remote_execution.http_status=200` 是旧程序固定填值，不是采集到的 HTTP 证据。读取旧诊断时标注该限制并改为未知；旧报告没有原始请求/响应的部分不能追溯补全。仅解释已有记录，不为补证据重发业务请求。

## 公开反馈

本地报告包含私密提示词、素材定位和原始 ID，不直接用作公开 Issue 正文。`issue-draft.md` 继续只保留公开白名单字段，排除原文、私密链接、路径、定位 ID、凭证指纹及原始响应。需要公开反馈时提供草稿供用户检查；只有用户明确要求发送时才提交 Issue 或联系管理员。

`AIHUB_ERROR_REPORT_THRESHOLD` 仍可读取旧配置，但不再延迟首错保存和提示。`AIHUB_SUPPORT_URL` 沿用已有服务支持入口；没有配置时只说联系当前服务管理员，不虚构联系方式。报告模块不改变网络重试、模型切换、确认或费用策略。
