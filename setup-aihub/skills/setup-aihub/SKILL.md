# Setup AIHub

用中文帮助用户管理 `aihub-studio` 与 `tikin-social` 的既有接入信息，英文请求沿用用户语言。技术标识与 **Secret Book** 保留原名。安装前按 [Plugin 使用说明](../../README.md) 核对可取得版本和宿主验证范围，不把配置成功说成鉴权或业务调用成功。

## 进入与选择

1. 沿用当前对话的服务、操作、来源、范围和原业务任务。用户只提供 `setup-aihub` 名称就是完整调用，不要求附加参数。“第一个”“刚才那个”“继续”按当前选择和任务解释。只有影响下一步的信息缺失时才询问。
2. 按 [宿主入口](references/hosts.md)核对实际宿主、运行环境与安装形态；查询安装记录时不读取业务凭证。源码目录、另一宿主的安装或当前轮看不到 Skill，均不能证明本宿主是否安装。安装、启用和本会话加载分别记录。
3. 没有目标时展示以下菜单，方括号填入**实际状态**（已安装／未安装／已安装未启用／已安装本会话未加载／安装状态待确认），附必要的未知原因：

   - **aihub-studio｜AIhub 创作与文档服务**【实际状态】
   - **tikin-social｜tikin 社交媒体数据服务**【实际状态】
   - **先检查当前已安装服务的配置**

   总览只检查已接入且确认已安装的服务；没有业务 caller 就用共享模式，不扫描各 Skill。选择目标未安装时提供“安装并继续配置／暂不安装，返回选择”。已有明确安装授权直接沿用；选服务本身不等于同意安装。安装中断保留任务，按宿主实际入口继续。
4. 已有任务编号时先读本 Skill，再用 helper `status`；无编号但要求继续时用 `list` 查同一宿主、环境、cwd 的未完成项。多个结果让用户选，不随意取最新。未知 schema 保持原文件；跨宿主任务不能消费旧确认。

## 本机检查与处理

按 [业务契约](references/consumers.md)定位真实 Plugin 实体，使用 [helper](references/helper.md) 的 `inspect`。保留真实业务 cwd、caller 和本次关闭全局的选择。共享报告只代表共享层。只读检查不创建配置或进度，不联网鉴权，不执行 `doctor`、完整 `tikin-setup`、路由初始化或更新。

凭证已可读且只是正常业务请求时，交回业务入口。缺项、主动更换/清除或有证据需修复时，报告字段、实际来源与依据。网络、余额、限流、权限错误各自解释，不能据此认定 Key 文本错误。地址与 Key 的对应关系也须核对。

沿用来源选择；未选择则提供 **自行填写本机文件／从 Secret Book 选择配置并保存**。先完成当前选择，再展开步骤，不一次要求用户填写服务、来源、路径和全部字段。

凭证文件只提供完整本机路径，供用户在本机编辑器填写；检查结果取自 helper 的无值报告。即使文件刚准备好且只有空示例，也不通过 Read、cat 等工具将文件原文带入会话，不用附件、`present_files` 或内容预览展示该文件；用户填写后仍只做无值复查。

- **手填**：首次共享使用两个业务 Plugin 各自既定 `.env`；修复使用真实来源，环境变量先定位注入位置。按 helper `start → plan → apply` 准备安全文件；展示 Plugin、字段、完整路径、范围、替换/保留项、覆盖及共享影响后，已有这次具体授权才执行 `apply`。用户在本机编辑，完整 Key 不进聊天、argv、进度或备份；回复“继续”后用原加载器复查。
- **Secret Book**：选择后必须读 [Secret Book 衔接](references/secret-book.md)。本次按凭证使用者取用已有表，远端只读；身份、候选、字段映射、具体目标与替换确认、实际保存由它负责。Setup 保留原任务并复查，不重复写入或重复询问相同摘要。委托前核对实际 Skill 实体；共享配置保留空 caller，最低版本与接入范围见衔接说明。真实表和宿主范围按实际证据报告。
- **清除**：仅在用户明确要求时规划。先通过业务加载器的只读删除投影展示将暴露的低层来源、仍然覆盖的高层、缺项或默认值，再确认选定文件和字段。helper 删除所选字段的全部有效重复赋值，保留其他行；不撤销远端 Key、不删除整份配置。tikin 清除地址时须核对保留的 Key 是否属于将生效的服务。
- **仅本轮**：沿用业务的安全进程注入或 Secret Book 临时执行入口，不建业务文件。宿主没有安全输入能力时说明实际限制并引导本机安全输入，不改为持久保存。

任务进度只存元数据。需要跨轮时才 `start`；安装、手填、确认和委托分别恢复。`continue` 不等于对待确认修改的新授权；文件、来源、业务实体或范围改变时重新规划受影响部分。`applying/result_unknown` 先 `reconcile` 读取现状，不重放、不覆盖恢复旧值。取消关闭未执行步骤，不回滚已保存配置。多 Plugin 请求各用一个任务，一项失败不影响已完成项。

## 结果与原任务

分别报告：目标 Plugin／宿主／环境／工作文件夹／真实 caller 或共享检查；本次保存或清除的文件与字段；实际生效来源、覆盖及本机读取结果；线上鉴权、宿主加载、真实业务调用的各自状态。当前版本没有登记经核实免费的鉴权入口，报告“线上鉴权未执行、业务调用未验证”，不借生成请求验证 Key。

返回原业务任务前检查其提交状态：未提交且内容、原授权仍有效才交回执行；已提交先查询原结果；状态未知先核对。helper 不提交业务，配置修复或恢复均不授权重新发送请求。必要时提供“请用 setup-aihub 继续任务〈编号〉”及实际刷新/新会话步骤。

本 Plugin 按当前宿主的完整 Plugin 渠道更新，不运行独立 Skill 更新脚本。准备账号、创建/撤销远端 Key、充值、模型路由和宿主模型设置属于其他任务；不要将它们混入凭证流程。
