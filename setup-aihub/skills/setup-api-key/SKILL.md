# Setup API Key

用中文帮助用户管理 `aihub-studio` 与 `tikin-social` 的既有接入信息，英文请求沿用用户语言。技术标识与 **Secret Book** 保留原名。安装前按 [Plugin 使用说明](../../README.md) 核对可取得版本和宿主验证范围，不把配置成功说成鉴权或业务调用成功。

## 进入与选择

1. 沿用当前对话的服务、操作、来源、范围和原业务任务。用户只提供 `setup-api-key` 名称就是完整调用，不要求附加参数。“第一个”“刚才那个”“继续”按当前选择和任务解释。只有影响下一步的信息缺失时才询问。
2. 按 [宿主入口](references/hosts.md)核对实际宿主、运行环境与安装形态；查询安装记录时不读取业务凭证。源码目录、另一宿主的安装或当前轮看不到 Skill，均不能证明本宿主是否安装。安装、启用和本会话加载分别记录。
3. 没有目标时展示以下菜单，方括号填入**实际状态**（已安装／未安装／已安装未启用／已安装本会话未加载／安装状态待确认），附必要的未知原因：

   - **aihub-studio｜AIhub 创作与文档服务**【实际状态】
   - **tikin-social｜tikin 社交媒体数据服务**【实际状态】
   - **先检查当前已安装服务的配置**

   总览只检查已接入且确认已安装的服务；没有业务 caller 就用共享模式，不扫描各 Skill。选择目标未安装时提供“安装并继续配置／暂不安装，返回选择”。已有明确安装授权直接沿用；选服务本身不等于同意安装。安装中断保留任务，按宿主实际入口继续。
4. 已有任务编号时先读本 Skill，再用 helper `status`；无编号但要求继续时用 `list` 查同一宿主、环境、cwd 的未完成项。只回复数字或“设为默认／本次跳过／不再提醒”，且正在回应默认设置菜单时，必须读 [Plugin默认设置检查](references/default-settings.md)，恢复该菜单的对象与阶段；不回到密钥选择菜单。多个结果让用户选，不随意取最新。未知 schema 保持原文件；跨宿主任务不能消费旧确认。

## 本机检查与处理

按 [业务契约](references/consumers.md)定位真实 Plugin 实体，使用 [helper](references/helper.md) 的 `inspect`。保留真实业务 cwd、caller 和本次关闭全局的选择。共享报告只代表共享层。只读检查不创建配置或进度，不联网鉴权，不执行 `doctor`、完整 `tikin-setup`、路由初始化或更新。

凭证已可读且只是正常业务请求时，交回业务入口。缺项、主动更换/清除或有证据需修复时，报告字段、实际来源与依据。网络、余额、限流、权限错误各自解释，不能据此认定 Key 文本错误。地址与 Key 的对应关系也须核对。

**配置、缺项或修复默认打开本机网页**，使用[网页入口](references/browser.md)。用户在页面选择手动填写或 Secret Book、范围并预览确认；沿用已明确的来源和范围，不重复提问。不要让用户把 Key 发到聊天，也不要读取凭证文件原文、截图已填写的真实 Key、用工具代填真实值或把值传入 argv。页面保存后只读无值状态，再通过原业务加载器复查。

- **手填网页**：本人在 password 输入框直接填写；首次共享使用业务 Plugin 既定 `.env`，项目首配使用 `.env.local`，修复回到真实生效来源。环境变量覆盖由 Agent 修复注入位置。页面列出实际目标、替换字段、服务地址及共享影响，点击确认才保存。
- **Secret Book 网页**：同一页面准备随包固定版本的读取核心和 Lark CLI，不要求额外安装 Secret Book Skill。本人选择现有连接或登录账号、确认实际身份、连接已有表、选择可见记录和字段映射，再确认业务保存。远端只读；缺列、缺 ID、权限不足由维护者处理。旧连接身份不匹配可在连接列表选择“修复所选连接的身份”；环境/项目来源在原来源修复，禁止另写低层遮盖。应用尚未配置时按 Lark CLI 的当前公开配置流程协助，不能借用 Hermes 私有配置。
- **本机编辑器**：仅当用户明确选择文件编辑或运行环境无浏览器时，沿用 [helper](references/helper.md) 的 `start → plan → apply` 安全准备；告诉用户完整文件位置和字段，用户本机填写后无值复查。原有已委托的 Secret Book 任务按[委托恢复](references/secret-book.md)完成，不新建重复保存流程。
- **清除**：仅在用户明确要求时规划。先通过业务加载器的只读删除投影展示将暴露的低层来源、仍然覆盖的高层、缺项或默认值，再确认选定文件和字段。helper 删除所选字段的全部有效重复赋值，保留其他行；不撤销远端 Key、不删除整份配置。tikin 清除地址时须核对保留的 Key 是否属于将生效的服务。
- **仅本轮**：沿用业务的安全进程注入或 Secret Book 临时执行入口，不建业务文件。宿主没有安全输入能力时说明实际限制并引导本机安全输入，不改为持久保存。

任务进度只存元数据。网页会话保存恢复编号；其他路径需要跨轮时才 `start`；安装、手填、确认和委托分别恢复。`continue` 不等于对待确认修改的新授权；文件、来源、业务实体或范围改变时重新规划受影响部分。`applying/result_unknown` 先 `reconcile` 读取现状，不重放、不覆盖恢复旧值。取消关闭未执行步骤，不回滚已保存配置。多 Plugin 请求各用一个任务，一项失败不影响已完成项。

## 结果与原任务

分别报告：目标 Plugin／宿主／环境／工作文件夹／真实 caller 或共享检查；本次保存或清除的文件与字段；实际生效来源、覆盖及本机读取结果；线上鉴权、宿主加载、真实业务调用的各自状态。当前版本没有登记经核实免费的鉴权入口，报告“线上鉴权未执行、业务调用未验证”，不借生成请求验证 Key。

**配置或修复成功后，结束回复前必须读取并执行 [Plugin默认设置检查](references/default-settings.md)。** 按开发者维护的指定清单检查当前宿主所有已安装对象，不限于本次配置的 Plugin。最后回复包含 **Plugin默认设置检查** 及逐项结果；需要提醒时明确告诉用户可以回复选项文字或数字，提供 **1. 设为默认 / 2. 本次跳过 / 3. 不再提醒**，使用具体用途说明和当前 Agent 名称。检查、选择及完整规则预览保存到当前任务，密钥完成状态独立保留；检查失败或未回答继续原任务。纯配置查询、清除或已有有效配置直接返回业务的分支不自动开启设置流程。

返回原业务任务前检查其提交状态：未提交且内容、原授权仍有效才交回执行；已提交先查询原结果；状态未知先核对。helper 不提交业务，配置修复或恢复均不授权重新发送请求。必要时提供“请用 setup-api-key 继续任务〈编号〉”及实际刷新/新会话步骤。

本 Plugin 按当前宿主的完整 Plugin 渠道更新，不运行独立 Skill 更新脚本。准备账号、创建/撤销远端 Key、充值、模型路由属于其他任务；客户端 AIhub 模型配置转交同包 [setup-agent-model](../setup-agent-model/SKILL.md)，不要混入本流程。
